## Approval and scope

The actual owner response is retained in
`failure-gate-installation-approval.json`. It approves local policy setup and
bounded installation checks, not ordinary cutover or live process reclaim.
No platform task IDs, historical approvals, protected identities, or task-board
hooks have been invented.

The policy selects the single registered tier stated in an exact locally
reviewed plan. `static` is restricted to non-governing documentation changes;
`standard` uses the existing typecheck and package tests plus local gate tests.
No arbitrary diagnostic selector or baseline-ignore capability is enabled.

## Implemented controls

- Transactional SQLite namespace and monotonic IDs, permanent terminal rows,
  one authoritative active tier, exact plan/definition/policy binding, stable
  captured decisions, derived per-tier audit status and idempotent activation.
- Bounded, no-follow regular-file inputs; traversal/symlink rejection; typed
  plan guards; no shell interpolation or caller-controlled command strings.
- Persistent per-event file trail, transaction linkage, pre-dispatch intent,
  confirmed independent watchdog registration and real start/finish events.
  Projection gaps remain visible and block work.
- Shared stable-inode writer lock, atomic run/resource reservation and retained
  exclusion on unknown lifecycle. The source-write route restricts changes to
  approved paths and checks prior content digests.
- Independent Linux watchdog/subreaper, private workload startup pipe, owned
  incarnation tracking, bounded output, monotonic execution deadlines and
  finite termination/capture. Only test-owned processes receive signals.
- Node 24 preload bounds default/named/nested tests and hooks, rejects disabled
  or enlarged timeouts, and retains the independent whole-process supervisor.
- Full required-step records, NOT_REACHED states, raw nonzero outcomes, TAP
  zero-test/cancellation/failure rejection, artifact digests and final manifest
  checks. Completion checks and terminal mutation hold writer protection together.
- Missing provenance defaults to unresolved potential regression. No catalog
  ignore, typecheck waiver or repair-removal authority is manufactured.
- Read-only evidence health/event views; scoped non-authorizing exports;
  actual isolated SQLite checkpoint/restore exercises that keep stale restores
  fenced and never resurrect permissions.
- Separate owner-direction completion mode with preserved validation/repairs.
  The current human-review adapter is local interactive review, not a platform
  approval service or a proxy for native platform completion.

## Limits and transitive scope

The approved maxima are in the policy. Installation accounting begins at the
first fixture dispatch and is never reset by store initialization. The real
installer caller is additionally narrowed to eight minutes per pass. Descendant
checks retain the original remaining budget; failed attempts consume it.

Command/hook/test-discovery definitions are conservatively pinned. Changed
definitions require renewed review; ordinary product edits invalidate run
snapshots without granting another tier. The workload environment discards
caller validation overrides and carries no service credentials.

Source manifests include relevant tracked/untracked regular inputs, canonical
Failure Gate sources, package/configuration files and installed pnpm metadata.
Logs, state, dependencies' bulk contents, build outputs and compiler caches
are excluded explicitly. Dependency metadata is not hostile-code attestation.
Tests use the existing mock DB/storage/model and ephemeral loopback listener.

## Preserved project behavior

Existing `pnpm typecheck`, `pnpm test`, package scripts, workflows and CI dispatch

Independent direct callers do not gain task authority or lose their invocation.

## Remaining applicable requirements

1. **Ordinary-route cutover:** separately scoped approval is absent. Actual
   ordinary local-plan review/activation/run/completion must be exercised and
   bound before enabling ACTIVE governance.
2. **Writer integration:** only cooperative participants of the new writer
   route are covered. Direct agent file tools, merge/checkout, API generation
   and other live writers are not verified participants. Completion remains
   blocked without this proof; hashes cannot detect reverted mid-run edits.
3. **Transitive/external coverage:** pinned definitions are not runtime
   attestation of every possible child argv. Uncontrolled direct scripts,
   independently launched validation, remote jobs and external-state
   equivalence remain unverified. They are not timeout exemptions.
4. **Protected containment:** Linux `/proc` plus subreaper is cooperative,
   not cgroup/pidfd or hostile-code/kernel-stall containment. Independent
   startup/lifecycle/evidence transport still needs host acceptance at each
   real finite entry point, including CLI admission reads and recovery.
5. **Recovery and backup readiness:** isolated fenced restore is proved only
   for the exercised host format. Live post-checkpoint reconciliation,
   allocator fencing/resumption, retained-run recovery, acknowledgement and
   backup cadence have not been accepted.
6. **Classification/waivers:** baseline history and direct earlier/comparison
   capabilities are absent. Rich failure lineage and governed repair resolution
   need their own authorized mappings; no uncatalogued failure can be ignored.
7. **Live reclaim:** independent attestation, authentic exact disruption
   approval, protected claims/revocation and acknowledged outcomes are unavailable.
   The reclaim route rejects without signals.
8. **Independent router verification:** no finalized primary task/dependency
   was supplied for this direct Build request. Required verifier creation is
   blocked; no Markdown file or guessed task ID is represented as a created
   independent verification task.

The existing work on bounded host validation and API generation coordination
must be reconciled with this route before cutover. Do not introduce two active
authorities, mutate those tasks, or use their platform status as local approval.
